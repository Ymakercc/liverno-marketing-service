# V2 基础自动营销试运行说明

## 当前目标

第一阶段只验证基础营销链路，只发送首封营销邮件。网页上设置的是“每天最终营销多少家精准公司”，不是“每天背调多少家公司”；营销总开关负责整套后台调度，Apollo 背调和 Brevo 发信各有独立开关：

1. n8n 从孚盟“公海客户”所属人下读取一批候选客户。
2. Apollo 匹配公司，搜索合适联系人并补全已验证邮箱。
3. 系统淘汰不精准客户、公司匹配失败、联系人不合适或邮箱不可用的客户；这些客户只算“背调过”，不算“营销成功”。
4. 对合格公司生成首封开发信，自动检查收件人、事实、字数和占位符，并将 Apollo 新信息回填孚盟。
5. 合格公司进入营销队列；系统继续读取和背调下一批候选客户，直到达到每日营销公司目标或内部背调上限。超过每日发送额度的邮件保留到后续日期。
6. 邮件按客户时区排队，n8n 每 15 分钟发送到期任务。
7. Brevo 回传送达、打开、点击、退信、退订和投诉。
8. 客户回复后，用户直接在 `marketing@kulon.com` 收件箱中手动判断是否跟进；本阶段不自动发送第二封。

例如：每日邮箱额度设置为 300 封，系统会持续背调候选公司；每家公司最多排入 5 个联系人，所以当天实际营销公司数可能是 60 家、100 家或其他数量，取决于找到的精准联系人数量。

飞书意向评分、收件箱自动解析和 AI 回复分类不在本阶段范围内。

## 默认安全状态

代码和 n8n 工作流已实现。新环境默认不会写入孚盟、启动自动营销或发送邮件；下面是小批量试运行建议值：

```dotenv
FUMENG_WRITEBACK_ENABLED=false
MARKETING_AUTOMATION_ENABLED=false
APOLLO_RESEARCH_ENABLED=true
EMAIL_SENDING_ENABLED=false
DAILY_SEND_LIMIT=10
DAILY_COMPANY_LIMIT=10
DAILY_RESEARCH_LIMIT=100
COMPANY_COOLDOWN_DAYS=7
```

源模板中的两条 n8n 工作流默认未激活；当前本机 n8n 已启用新版定时工作流：

- `KULON 01 - Apollo补全与营销排队`
- `KULON 02 - 按时区发送已排期邮件`

候选漏斗每 10 分钟最多背调 10 家并继续累计，发送调度每 15 分钟运行。营销总开关关闭时两条调度都停止；`APOLLO_RESEARCH_ENABLED=false` 只停止新增背调，`EMAIL_SENDING_ENABLED=false` 只停止 Brevo 发信，已排队任务始终保留。Apollo 明确返回额度耗尽后，服务会自动持久化关闭背调，但不会关闭总开关或发信开关。

## 必要配置

### 孚盟

```dotenv
FUMENG_BASE_URL=https://opengw.fumamx.com
FUMENG_APP_ID=
FUMENG_APP_SECRET=
FUMENG_PUBLIC_SEA_OWNER_ID=<FUMENG_PUBLIC_SEA_OWNER_ID>
FUMENG_EMAIL_TRACK_MODE_ID=<FUMENG_EMAIL_TRACK_MODE_ID>
```

客户候选规则：

- 背调前不要求客户必须是“线索”或“意向”；空状态及其他未明确禁止的状态都可进入背调。
- 只在背调前排除 `custState=3` 成交、`5` 停业、`6` 拒联；客户是否精准由 Apollo 和 AI 背调结果判断。
- “公海客户”指孚盟所属人账号，不使用 `seasFlag` 判断。

### Apollo

```dotenv
APOLLO_BASE_URL=https://api.apollo.io
APOLLO_API_KEY=
APOLLO_MAX_PEOPLE_PER_COMPANY=5
APOLLO_MINIMUM_COMPANY_SCORE=75
```

填写 Key 后运行 `npm run smoke:apollo`。该命令会验证公司补全、公司搜索、联系人搜索和联系人补全四项权限，People Match 最多消耗 1 个 Apollo 邮箱 Credit，输出不包含邮箱或 Key。正式处理时，系统先搜索，再为每家公司最多补全并评估 5 个候选联系人。

### 三个每日数量

- `DAILY_COMPANY_LIMIT`：每日最终进入营销队列的公司目标/上限，可在网页修改，范围 1-300。
- `DAILY_SEND_LIMIT`：每日邮箱发送上限，当前为 300；同一家公司首轮最多 5 个联系人。
- `DAILY_RESEARCH_LIMIT`：内部背调安全上限，不是 Apollo 账户剩余额度；用于防止候选质量过低时无限消耗 Credits，当前生产配置为 1000，范围 10-1000。
- `APOLLO_RESEARCH_ENABLED`：新增 Apollo 背调开关。额度耗尽后自动关闭，补充额度后可在网页手动恢复。

三者的关系是：系统先背调，再筛选，最后营销。背调数不等于营销公司数，营销公司数也不等于邮件数。

当 Apollo 没有额度但队列仍有邮件时，正确状态为：营销总开关开启、Apollo 背调关闭、Brevo 发信开启。系统不再调用 Apollo，只按时区与每日 300 封上限继续发送队列。

### 中转站

```dotenv
OPENAI_BASE_URL=https://你的中转站地址/v1
OPENAI_API_KEY=
OPENAI_MODEL=中转站提供的模型名
OPENAI_API_STYLE=chat_completions
```

联系人邮箱不发送给大模型；模型只接收公司、官网、国家、行业、联系人姓名和职位。

### Brevo

```dotenv
BREVO_API_KEY=
BREVO_SENDER_EMAIL=marketing@kulon.com
BREVO_REPLY_TO_EMAIL=marketing@kulon.com
BREVO_SENDER_NAME=MEAN WELL KULON TEAM
EMAIL_SENDING_ENABLED=false
```

Webhook 公网入口为 `https://brevo-webhook.kulon.net/api/webhooks/brevo`。公网只暴露该路径并转发到 `127.0.0.1:8790`，不暴露控制台。

## 孚盟回填规则

- 客户官网为空时才补充 `web`。
- 已有联系人只补空白的邮箱、职位和 LinkedIn。
- 新 Apollo 联系人作为孚盟子档新增，不替换原主联系人。
- 不自动修改客户名、所属人、客户状态和人工已填内容。
- 发送成功后尝试新建孚盟邮件跟进；跟进写入失败不会造成邮件重发。
- `FUMENG_EMAIL_TRACK_MODE_ID=<FUMENG_EMAIL_TRACK_MODE_ID>` 对应孚盟字典中的“邮件营销”。

## 队列与停止规则

- 一家公司首轮最多发 5 个联系人，实际数量取决于 Apollo 找到的有效邮箱。
- 同一客户或邮箱 7 天内不重复排队。
- 公司匹配失败或联系人未找到也记录 7 天冷却，避免反复消耗 Apollo Credits。
- 候选筛选会翻页扫描完整营销公海池，直到找够本批客户或到达数据末尾。
- 任务使用 `campaign + customerId + email` 生成幂等键。
- 每日营销公司数可在网页设置，系统最多处理该数量的公司；邮件队列超过 `DAILY_SEND_LIMIT` 后不会停止背调，未发邮件会保留到后续日期。系统每天最多调用 Apollo 背调 `DAILY_RESEARCH_LIMIT` 次。
- 每日最大发送邮件数为 `DAILY_SEND_LIMIT`，且代码强制不超过 300；超过当天额度的任务留在队列，第二天继续发送。
- 发送前重新读取孚盟客户状态和联系人。
- 硬退信、无效邮箱、拦截、退订或投诉会进入本地禁止发送表并取消未发任务。

## 基础启用顺序

1. 创建 Key 前运行 `npm run preflight -- --allow-missing-apollo`，确认除 Apollo 外都已就绪。
2. 填入 `APOLLO_API_KEY`，保持两个写开关为 `false`。
3. 运行 `npm run preflight`、`npm run smoke:apollo` 和 `npm test`。
4. 为孚盟应用开启 `NewBF001` 编辑、`NewBF003` 新增/编辑、`NewBF004` 新增权限。
5. 将 `FUMENG_WRITEBACK_ENABLED=true`，用 1 个可控客户验证新增联系人和官网回填。
6. 在网页确认每日邮箱额度和营销开关，运行候选工作流，检查实际进入营销队列的收件人、主题、时区和质量分数；营销公司数量会随有效联系人数量变化。
7. 将 `EMAIL_SENDING_ENABLED=true`，重启 `npm run start:tracking`。
8. 手动运行发送工作流，在网页和 Brevo 同时确认结果。
9. 当前本机 n8n 已激活两条新版定时工作流；重新导入源模板后，需要在 n8n 中发布/激活对应版本。

## 密钥与数据

- 真实 Key 和 Secret 只写入本机 `.env` 或 n8n 本地数据库。
- `.env`、`.data/`、n8n 执行记录、客户数据和临时导入副本不得提交 Git。
- 网页可修改 OpenAI 兼容中转站配置；Key 只写入本机 `.env`，页面仅显示是否已配置及末尾四位，不回显完整值。
- 未配置 `SETTINGS_ADMIN_TOKEN` 时，中转站设置只接受本机和私有局域网请求；配置后必须在页面提供该令牌。
